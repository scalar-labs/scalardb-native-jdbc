## [v3.20.0] - 2026-10-30

### Enhancements

- The first release of ScalarDB Native JDBC, a JDBC driver for a database that holds both ordinary tables and ScalarDB tables. The application uses the database's own SQL and transactions on both: a transaction through the driver is one native transaction, ACID across both kinds of table, and ScalarDB's transactions on the same tables keep their guarantees. The driver wraps the database's own JDBC driver, which the application supplies, and connects with `jdbc:scalardb-native:<database>:...` URLs. It is published to Maven Central as `com.scalar-labs:scalardb-native-jdbc` and runs on Java 11 or later. See `docs/getting-started.md`.
- PostgreSQL, MySQL, MariaDB and SQL Server are supported at READ COMMITTED, SNAPSHOT and SERIALIZABLE, and Oracle at READ COMMITTED and SNAPSHOT, tested against ScalarDB 3.19.1; ScalarDB 3.20 writes the same transaction metadata columns and states as 3.19. A connection starts at SNAPSHOT, ScalarDB's default. Both of ScalarDB's layouts are served, inline and decoupled transaction metadata, and an application names a table the same way in either. See `docs/transactions.md` and `docs/sql-support.md`.
- `scalardb-native-tools`, shipped as `scalardb-native-tools-<version>.zip` on the GitHub release, runs the one-time setup the driver needs on ScalarDB tables, checks it, undoes it, and adds a table to it while applications run. With `--backfill` the setup also writes the transaction metadata of imported tables, which is off by default; `backfill` runs it alone and repairs the rows ScalarDB leaves with NULL metadata, which `check` reports. See `docs/setting-up-tables.md`.
- `snsql`, a psql-like interactive shell that goes through the driver on all five databases, shipped as `scalardb-native-shell-<version>.zip` on the GitHub release. See `docs/snsql.md`.
- Every error the driver raises carries an SQLState, listed with its cause and what to do about it in `docs/errors.md`.
