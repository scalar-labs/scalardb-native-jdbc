## [v3.20.2] - 2026-11-26

### Bug fixes

- On PostgreSQL, a duplicate key on an INSERT into a ScalarDB table no longer lets the transaction commit its other writes. PostgreSQL aborts a transaction when a statement in it fails, but after this duplicate the driver let the transaction go on, so a later `COMMIT` kept the writes before it. The transaction now fails as PostgreSQL's own does: later statements and `commit()` fail with `25P02`, as on PostgreSQL, until the application rolls back, either the whole transaction or to a savepoint set before the duplicate. Under pgjdbc's `autosave`, the transaction goes on, as it does on PostgreSQL there. The other engines are unchanged.
- In `snsql`, a meta-command such as `\dt ec.*;` now drops its trailing semicolons, as psql does. It had searched for a table named `ec.*;` and found none.
