# ScalarDB Native JDBC 3.20.0-beta.1

Second private preview, certified against the ScalarDB 3.20 line on PostgreSQL, MySQL, MariaDB and
SQL Server at READ COMMITTED, SNAPSHOT and SERIALIZABLE, and on Oracle at READ COMMITTED and SNAPSHOT.

The application uses its database's own SQL and transactions across ordinary tables and ScalarDB
tables, and ScalarDB's transactions on the same tables keep their guarantees. New since
3.19.0-alpha.1:

- writes, anchored reads and locking reads (`FOR UPDATE`, `FOR SHARE` and the engines' spellings) on
  all five engines;
- SNAPSHOT and SERIALIZABLE, mapped to each engine as the README's "Isolation levels" describes;
- the inline layout, ScalarDB's default, beside the decoupled one: the metadata columns are kept from
  the application;
- `scalardb-native-tools`: the setup that prepares ScalarDB tables for the driver, its check and its
  teardown;
- `snsql` in `scalardb-native-shell`, a psql-like interactive shell through the driver;
- samples with plain JDBC and with Spring Data JDBC, in `samples/`.

Getting started, and what this preview supports and refuses: the README, sections "Getting started"
and "Preview scope". The design is in docs/design.md.

## Artifacts

- `scalardb-native-jdbc-3.20.0-beta.1.jar`: the driver, Java 11 or later. It needs JSQLParser 5.4 and
  slf4j-api on the classpath, and the application's own JDBC driver.
- `-sources.jar`, `-javadoc.jar`, and the POM listing the dependencies.
- `scalardb-native-tools-3.20.0-beta.1.zip` and `scalardb-native-shell-3.20.0-beta.1.zip`.

## Verified

- Unit and integration tests on all five engines and both layouts against ScalarDB 3.20, including
  interleavings of driver and ScalarDB transactions and the samples as acceptance tests.

## Known limits

- Oracle refuses SERIALIZABLE. On MySQL a read at SERIALIZABLE in a read-only transaction is refused
  with `25006`.
- A table imported or created after the application loaded the driver's catalog: run the setup
  again and restart the application (README, "Getting started").
- Rows read through a RIGHT or FULL JOIN, a derived table, a CTE or a UNION are not anchored: a later
  write in the same transaction does not check them for changes.
- Per-engine restrictions on INSERT, `RETURNING`, generated keys and hints: README, "Preview scope".
- No license yet; not on Maven Central.
