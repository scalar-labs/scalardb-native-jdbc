# ScalarDB Native JDBC 3.19.0-alpha.1

First private preview, certified for PostgreSQL at READ COMMITTED against the ScalarDB 3.19 line.

The application uses PostgreSQL's own SQL and transactions across ordinary tables and ScalarDB tables
in the decoupled layout, and ScalarDB's transactions on the same tables keep their guarantees:

- reads see committed data only, never a ScalarDB transaction's prepared rows;
- writes leave the row metadata ScalarDB checks, so neither side overwrites the other's update
  unseen: the loser gets `40001` and retries;
- one native transaction spans both kinds of table.

Getting started, and what this preview supports and refuses: the README, sections "Getting started"
and "Preview scope". The design is in docs/design.md.

## Artifacts

- `scalardb-native-jdbc-3.19.0-alpha.1.jar`: the driver, Java 11 or later. It needs JSQLParser 5.4
  and slf4j-api on the classpath, and the application's PostgreSQL driver.
- `-sources.jar`, `-javadoc.jar`, and the POM listing the dependencies.

## Verified

- Unit and integration tests on PostgreSQL 16, including step-by-step interleavings of driver and
  ScalarDB transactions under ScalarDB's READ_COMMITTED and SNAPSHOT levels; reads also on MySQL,
  MariaDB, SQL Server and Oracle.
- The built jar on JDK 17 against PostgreSQL 16 and ScalarDB 3.19.1: setup, a transaction across a
  ScalarDB and an ordinary table, ScalarDB reading the driver's write, the driver reading ScalarDB's.
  Java 11 itself was not run; the jar is compiled with `--release 11`.

## Known limits

- PostgreSQL only for writes, READ COMMITTED only, decoupled tables only.
- Rows read through a RIGHT or FULL JOIN, a derived table, a CTE or a UNION are not anchored: a
  later write in the same transaction does not check them for changes.
- A new statement text costs 0.6-0.8 ms on PostgreSQL (the server plan check); a repeated one a few
  microseconds.
- No license yet; not on Maven Central.
